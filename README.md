# 해외축구 일정·순위

football-data.org 무료 API로 만든 해외축구 정보 사이트예요.
경기 일정, 결과, 순위, 득점 순위를 모두 한국 시간 기준으로 보여 줍니다.

## 실행하기

```bash
npm install
cp .env.example .env.local   # 복사한 파일에 football-data.org 키와 Supabase 주소·키를 넣어 주세요.
npm run dev                  # http://localhost:3000
```

배포 전처럼 확인하려면 `npm run build` 후 `npm run start`를 실행하세요.
개발 모드에서는 캐시와 링크 미리 불러오기가 실제 배포와 다르게 동작해요.

## API 호출 한도 관리

무료 플랜은 분당 10회까지만 호출할 수 있어서 이렇게 막아 두었어요.

- 같은 데이터는 정해진 간격에 한 번만 불러요. 경기는 5분, 순위는 10분, 득점 순위는 30분이에요.
- 페이지 결과와 API 응답을 둘 다 저장해요. Vercel에서는 API 응답 저장소를 모든 서버가 같이 써요.
- 빌드할 때는 홈과 프리미어리그 페이지만 미리 만들어요. API는 4번만 불러요.
- 나머지 대회 페이지는 첫 방문 때 만들어 저장하고, 다음 방문자부터는 저장된 페이지를 받아요.
- 주요 메뉴와 날짜 버튼은 링크 미리 불러오기를 꺼 두었어요.
  날짜 선택 줄이 선택한 날짜를 따라 움직여서, 화면에 보이는 날짜를 모두 미리 조회하면 API 호출이 늘 수 있어요.
  리그 순위·일정은 경기 화면 안의 선택 메뉴로 이동해요.
- 경기 필터는 이미 받은 목록에서 적용해 추가 API 요청이 없어요. 내 팀 필터의 회원 정보는 공용 경기 캐시 밖에서 따로 읽어요.
- 오늘 경기 목록과 시작 전·진행 중 경기 화면은 보이는 동안 5분마다 확인하고, 숨긴 탭에서는 멈춰요.
  새로고침도 서버 캐시를 유지하므로 제공처의 데이터가 그대로면 점수가 같을 수 있어요.
  데이터 기준 시각은 API 응답의 시각이고, 화면을 새로 연 시각으로 덮어쓰지 않아요.

캐시가 실제로 쓰이는지 확인하려면 이렇게 실행하세요.

```bash
NEXT_PRIVATE_DEBUG_CACHE=1 npm run start
```

## 화면 속도

- **팀 엠블럼은** Next.js 이미지 최적화로 작은 WebP로 바꿔서 이 사이트 주소에서 내려줘요.
  원본 PNG보다 용량이 훨씬 작고, 엠블럼 서버까지 따로 갔다 오지 않아요.
  만드는 크기를 세 가지로 제한해서 Vercel 무료 플랜의 이미지 변환 한도 안에 들어와요.
- **글꼴은** 웹폰트를 받지 않고 기기에 있는 한글 글꼴을 써요.
  글꼴 파일을 기다리거나 도중에 글꼴이 바뀌면서 화면이 다시 그려지는 일이 없어요.
  Pretendard로 되돌리고 싶으면 `src/app/layout.tsx`에 Pretendard CSS 링크를 다시 넣으면 돼요.

## 화면 디자인

- 밝은 화면은 경기장색 헤더와 라임색 선택 표시를 써요. 다크 모드는 블랙·차콜 배경에 흰색·회색 버튼을 쓰고, 초록색은 진행 중 표시와 작은 포인트에만 남겨요. 모바일 브라우저 주소창도 차콜색으로 맞춰요.
- 경기 센터 머리에는 선택한 날짜의 실제 경기·대회·진행 중 수와 대표 경기를 보여요. 이미 받은 경기로 만들어 추가 API 호출은 없어요.
- 리그별 경기 카드는 넓은 화면에서 두 열, 휴대폰에서 한 열이에요. 경기 상세는 큰 엠블럼·스코어와 축구장 라인으로 구성해요.
- 카페와 리그 배너도 같은 축구장 모양을 써요. 카페 이름·소개는 유지하고, 운영자가 고른 배너 색은 밝은 화면에서 배경으로, 다크 모드에서 얇은 포인트로 보여요.

- 상단 주요 메뉴는 경기·카페·예측·스쿼드·게임이에요. 리그 선택은 경기 화면 안에, 게시판 선택은 카페 안에 있어요.
- 날짜는 선택한 날을 포함한 일주일, 달력 입력, 오늘 버튼으로 이동해요. 오늘 기준 앞뒤 60일까지만 선택할 수 있어요.
- 경기 목록은 전체·진행 중·예정·종료, 리그, 내 팀으로 좁힐 수 있어요. 연기·취소·중단 경기는 전체에서 확인해요.
- 휴대폰의 카페 글 목록은 제목을 두 줄까지 표시하고 작성자·시각·댓글 수를 우선 보여 줘요. 등급·조회·추천은 넓은 화면에서 함께 보여 줘요.
- 공통 카드 모양은 `src/components/ui.ts`에 모아 두었어요. 여기만 바꾸면 모든 카드가 같이 바뀌어요.
- 대회 페이지 머리는 대회마다 고유색을 써요. 색은 `src/lib/competitions.ts`의 `color`이고,
  흰 글씨가 잘 읽히도록 대비가 4.5:1 이상인 진한 색만 넣어 주세요.
- 날짜를 앞뒤로 옮기면 경기 목록이 그 방향으로 밀려 들어와요. 브라우저의 View Transitions 기능을 써서
  지원하지 않는 브라우저나 움직임 줄이기를 켠 기기에서는 애니메이션 없이 바로 바뀌어요.

## 카페

축구 팬끼리 이야기하는 공간이에요. 게시판(자유·리그별·인기글), 추천, 댓글과 답글, 경기별 승부 예측과 실시간 응원톡이 있어요.
내 정보 화면에서 닉네임을 바꾸고 5대 리그 중 응원하는 팀을 고를 수 있어요. 고른 팀 엠블럼이 프로필 그림이 되고,
홈 화면 맨 위에 내 팀의 순위, 다음 경기, 최근 5경기 결과가 떠요.
글과 회원 정보는 [Supabase](https://supabase.com) 무료 플랜에 저장하고, 카카오·구글 계정으로 로그인해요.
글 읽기는 누구나, 글·댓글·추천·응원톡은 로그인하고 닉네임을 정한 회원만 할 수 있어요.

### 카페 설정

1. supabase.com에서 새 프로젝트를 만들어요. 지역은 Northeast Asia (Seoul)가 빨라요.
2. 대시보드의 **SQL Editor**에 `supabase/schema.sql` 내용을 통째로 붙여 넣고 Run을 눌러요.
   여러 번 실행해도 괜찮아서, 이 파일을 고친 뒤에도 다시 실행하면 돼요.
3. 프로젝트 주소(Project URL)와 Publishable key를 복사해 `.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`에 넣어요.
   - 프로젝트 주소는 `https://abcdefghijklmnopqrst.supabase.co`처럼 생겼고, 가운데 글자는 프로젝트마다 다른 프로젝트 ID예요.
     대시보드 위쪽 **Connect** 버튼을 누르면 보여요.
     대시보드 주소창 `supabase.com/dashboard/project/abcdefghijklmnopqrst`의 맨 끝도 같은 프로젝트 ID예요.
   - Publishable key는 **Project Settings > API Keys**에 있고 `sb_publishable_`로 시작해요. 이 두 칸에는 Secret key를 넣지 마세요.
   Vercel 프로젝트의 Environment Variables에도 같은 값을 넣어요. 빌드할 때 화면에 박히는 값이라 바꾸면 다시 배포해야 해요.
   - 승부 예측 골을 주고 선수 맞히기 사진을 보여 주려면 같은 화면의 **Secret key**(`sb_secret_`로 시작)를 `SUPABASE_SECRET_KEY`에 넣어요.
     서버에서만 쓰는 키라 이름 앞에 `NEXT_PUBLIC_`을 절대 붙이면 안 돼요. Vercel에도 같은 이름으로 넣어요.
     비워 두면 예측 골 지급과 선수 맞히기만 멈추고 출석 골과 나머지 기능은 그대로 돌아가요.
4. **Authentication > URL Configuration**에서
   - Site URL에 배포한 사이트 주소(`https://내도메인`)를 넣어요. 아직 배포 전이면 `http://localhost:3000`을 넣어요.
   - Redirect URLs에 `http://localhost:3000/**`을 추가해요. 로컬에서 로그인하면 로컬로 돌아오게 해 줘요.
     돌아갈 화면이 `/auth/callback?next=...`처럼 뒤에 붙어서 `/**`까지 적어야 맞아요.
     주소가 목록에 없으면 Supabase가 Site URL로 보내 버려서 로그인이 끝나지 않아요.
   - Site URL과 같은 주소는 목록에 없어도 돼요. Vercel 미리보기처럼 다른 주소에서도 로그인하려면 그 주소에 `/**`를 붙여 추가해요.
5. **Authentication > Sign In / Providers**에서 로그인 방식을 켜요.
   카카오·구글 쪽에는 Supabase 콜백 주소를 넣어요. 3번의 프로젝트 주소 뒤에 `/auth/v1/callback`을 붙인 것으로,
   `https://abcdefghijklmnopqrst.supabase.co/auth/v1/callback`처럼 생겼어요.
   Supabase에서 카카오나 구글 설정을 열면 **Callback URL (for OAuth)** 칸에 이 주소가 나와서 그대로 복사하면 돼요.
   - 카카오: [Kakao Developers](https://developers.kakao.com)에서 앱을 만들고 카카오 로그인을 켠 뒤,
     Redirect URI에 Supabase 콜백 주소를 넣어요.
     REST API 키와 Client Secret을 Supabase 카카오 설정에 넣어요.
     동의항목에서 닉네임, 프로필 사진, 카카오계정(이메일)을 모두 켜요. 하나라도 꺼져 있으면 KOE205 오류가 나요.
     Supabase가 이 세 가지를 늘 같이 요청하고, 코드에서 뺄 수 없어요.
     이메일은 비즈 앱에서만 켤 수 있어요. 사업자가 아니어도 **앱 > 일반 > 비즈니스 정보**에서 개인 개발자 비즈 앱으로 바꾸면 돼요.
     카페는 이메일을 쓰지 않으니 이메일은 선택 동의로 두고, Supabase 카카오 설정에서 **Allow users without an email**을 켜요.
     자세한 내용은 [Supabase 카카오 로그인 문서](https://supabase.com/docs/guides/auth/social-login/auth-kakao)에 있어요.
   - 구글: [Google Cloud Console](https://console.cloud.google.com)에서 OAuth 클라이언트를 만들고
     승인된 리디렉션 URI에 같은 Supabase 콜백 주소를 넣어요.
     자세한 순서는 [Supabase 구글 로그인 문서](https://supabase.com/docs/guides/auth/social-login/auth-google)에 있어요.
   - 한쪽만 쓰려면 `src/lib/cafe/config.ts`의 `LOGIN_PROVIDERS`에서 다른 쪽을 지워요.

### 카페 운영

- **회원 태그**: 댓글·답글에서 `@`를 입력하면 카페 회원을 닉네임으로 찾아 선택할 수 있어요.
  방향키와 Enter/Tab 또는 터치로 선택해요. 정확한 `@닉네임`을 직접 써도 태그돼요.
  태그된 회원의 내 소식에 알림이 생기고, 누르면 해당 댓글로 이동해요.
  본인 태그는 알리지 않고, 같은 댓글에서 댓글·답글·태그 대상이 겹치면 태그 알림 하나만 보내요.
  이메일과 URL 속 `@`는 태그하지 않아요. 작성 당시 회원을 저장하므로 닉네임이 바뀌어도 대상이 바뀌지 않아요.
- **업데이트 알림**: `/cafe/admin`의 ‘업데이트 알림’에서 버전·제목·내용을 등록해요.
  당시 가입한 모든 회원에게 알림이 생기고 `/cafe/updates`에 내용이 남아요.
  같은 버전은 두 번 등록할 수 없어요. 코드 배포만으로 알림을 보내지는 않으므로 배포 후 운영자가 변경 내용을 등록해 주세요.
  알림 배지는 실시간으로 갱신하고, 연결이 끊겨도 화면을 보고 있으면 30초마다 확인해요.
  내 소식 화면에 표시된 항목만 읽음으로 바꿔서 그사이 도착한 알림은 남겨 둬요.
  50개씩 쪽을 넘겨 이전 소식도 읽을 수 있어요.
- **이 기능을 배포하기 전**: 아래 기존 절차대로 `supabase/schema.sql` 전체를 SQL Editor에서 실행해 주세요.
  `comments.mentions`, `site_updates`, 태그·업데이트 알림 트리거, 읽음 함수와 실시간 전송 설정이 추가돼요.
- **태그·알림 검증**: `npm run test:cafe`는 로컬 메모리의 PostgreSQL(PGlite)에서 전체 스키마를 실행해요.
  중복·자기 태그, 기존 댓글 알림, 권한, 업데이트 중복 방지, 읽음 범위, 삭제와 스키마 재실행을 확인해요.
  운영 DB에는 연결하지 않아요.

- **매니저 지정**: SQL Editor에서 아래처럼 실행하면 그 회원이 아무 글·댓글·응원톡이나 지울 수 있어요.
  닉네임 옆에 "매니저" 표시도 붙어요.

  ```sql
  update public.profiles set is_manager = true where nickname = '내닉네임';
  ```

- **운영자 지정**: 운영자는 매니저 권한에 더해 카페 관리 화면(`/cafe/admin`)을 쓸 수 있어요. 닉네임 옆에 "운영자" 표시가 붙고,
  계정 메뉴에 **카페 관리**가 생겨요. 매니저처럼 SQL Editor에서만 정해요.

  ```sql
  update public.profiles set is_admin = true where nickname = '내닉네임';
  ```

- **카페 관리 화면**에서 하는 일
  - 배너의 카페 이름·소개·색을 바꿔요. 고치는 대로 미리 보기가 바뀌고, 저장하면 다음에 여는 모든 화면에 바로 보여요.
  - 배너 아래 한 줄 공지를 켜고 꺼요. 링크는 `/`로 시작하는 이 사이트 주소나 `https://` 주소만 넣을 수 있어요.
  - **글쓰기 잠금**(점검 모드)을 켜면 매니저와 운영자를 뺀 회원은 글·댓글·응원톡을 쓰거나 글을 고칠 수 없어요.
    읽기, 추천, 승부 예측은 그대로 되고, 모든 카페 화면에 잠금 안내 띠가 떠요. DB 규칙이라 화면을 거치지 않아도 막혀요.
  - 글 화면 아래의 **공지로 올리기**를 누르면 그 게시판 첫 쪽 맨 위에 보여요. 전체글에는 최근에 올린 공지 5개가 나와요.
  - 설정을 바꾸거나 공지를 올리고 내리면 누가 언제 무엇을 바꿨는지 **운영 기록**에 남아요. 1년이 지난 기록은 지워져요.
- 카페 설정은 DB의 `cafe_settings`에 한 줄로 있어요. SQL Editor에서 직접 고쳐도 되는데, 그때는 화면에 한 시간 안에 반영돼요.

- **schema.sql이 바뀌었을 때**: 새 기능에 DB 칸이 늘면 `supabase/schema.sql`이 바뀌어요.
  배포하기 **전에** SQL Editor에서 파일 전체를 다시 실행해요. 있던 글과 회원은 그대로 남아요.
  순서가 바뀌면 새 코드가 아직 없는 칸을 읽으려다 카페 화면이 오류를 내요.
- **게시판 바꾸기**: `src/lib/cafe/boards.ts`의 목록과 `supabase/schema.sql`의 `posts_board_check`를 같이 고치고 SQL을 다시 실행해요.
- **도배 방지**: 글은 30초, 댓글은 5초, 응원톡은 3초에 한 번만 쓸 수 있어요. DB 규칙이라 화면을 거치지 않아도 막혀요.
- **인기글 기준**: 추천 3개 이상이에요. `src/lib/cafe/config.ts`의 `BEST_LIKES`에서 바꿔요.

### 카페가 동작하는 방식

- 글 목록과 본문은 저장해 두지 않고 볼 때마다 Supabase에서 읽어요. 그래서 새 글이 바로 보이고,
  경기 API 호출 한도와도 상관없어요. 게시판 머리와 화면 뼈대는 미리 만들어 둬서 바로 떠요.
- 경기 화면은 날짜별 경기 화면과 같은 저장된 API 응답에서 경기를 찾아서 API 호출이 늘지 않아요.
  그래서 경기 화면도 오늘 기준 앞뒤 60일 안의 경기만 열려요. 경기 줄 링크는 미리 불러오기를 꺼 두었어요.
- 응원톡은 Supabase 실시간 전송으로 새 메시지를 받아요. 보내기는 서버를 거쳐서 로그인과 글자 수를 다시 확인해요.
- 응원팀 목록은 리그 화면의 순위표 캐시를 같이 써요. 고를 때 팀 이름과 엠블럼 주소를 회원 정보에 같이 저장해서,
  글 목록에 엠블럼을 그릴 때는 경기 API를 부르지 않아요. 엠블럼은 football-data.org 그림만 저장되게 DB가 막아요.
- 홈의 내 팀 카드는 순위표와 리그·챔스 일정 캐시로 만들어서 API 호출이 거의 늘지 않아요. 로그인한 회원에게만 보여요.
- 답글은 댓글 아래 한 단계만 달려요. 답글이 달린 댓글을 지우면 "삭제된 댓글" 자리로 남고, 답글이 다 지워지면 자리도 사라져요.
- 승부 예측은 킥오프 전까지 홈 승·무승부·원정 승 중 하나를 고르고 바꿀 수 있어요.
  연장까지의 결과로 채점하고, 승부차기로 갈린 경기는 무승부로 쳐요.
  킥오프 시각과 결과는 경기 API에만 있어서, 고친 시각을 DB가 직접 적고 순위를 셀 때 킥오프 뒤에 고친 예측을 빼요.
- 예측 순위(`/cafe/predict`)는 이번 시즌 대회별 경기 목록에서 결과를 찾아 5분마다 새로 계산해요.
- **골**은 돈 가치가 없는 자랑용 포인트예요. 하루 첫 방문 때 자동으로 출석해서 10골, 7일 연속마다 30골을 더 받아요.
  승부 예측을 맞히면 10골, 5명 이상 참여한 경기에서 적중자가 30% 이하면 10골을 더 받고, 예측 골은 하루 50골까지예요.
  선수 맞히기 정답은 1골에 연승마다 1골씩 더해서 5연승부터 5골이에요.
  골에 따라 새싹(0) → 유망주(100) → 주전(300) → 에이스(800) → 레전드(2000) 등급 배지가 닉네임 옆에 붙어요.
- 골은 회원이 직접 바꿀 수 없어요. 출석은 DB 함수(`check_in`)가 한국 날짜로 하루 한 번만 주고,
  예측 골은 서버가 경기 결과를 확인한 뒤 비밀 키로만 부를 수 있는 `settle_match`가 줘요.
  정산은 회원이 홈, 내 정보, 예측 순위, 끝난 경기 화면을 볼 때 화면을 다 보낸 뒤 5분에 한 번씩 돌아요.
  골을 현금이나 상품으로 바꿔 주거나 예측에 골을 걸게 하면 사행성 문제가 생길 수 있으니 자랑용으로만 써 주세요.
- **골 상점**(`/cafe/shop`)에서 골로 닉네임 색과 프로필 테두리를 사서 쓸 수 있어요.
  등급은 지금까지 모은 골로 정해서, 골을 써도 등급은 그대로고 쓸 수 있는 골만 줄어요.
  가격은 DB의 `shop_items`에, 보이는 모양은 `src/lib/cafe/shop.ts`에 있어서 아이템을 늘리면 두 곳을 같이 고쳐요.
  사기와 쓰기는 DB 함수(`buy_item`, `equip_item`)로만 해서, 골이 모자라거나 안 산 아이템은 쓸 수 없어요.
- **내 소식**(`/cafe/notifications`)은 내 글에 댓글, 내 댓글에 답글, 내 글에 추천이 달리거나 승부 예측을 맞히면 쌓여요.
  안 읽은 수가 닉네임 칩에 빨간 숫자로 붙고, 내 소식 화면을 열면 다 읽음이 돼요. 60일이 지난 소식은 지워져요.
  소식은 DB 트리거와 `settle_match`만 만들어서 회원이 가짜 소식을 넣을 수 없고, 내 소식만 볼 수 있어요.
- 권한 규칙(본인 글만 수정, 매니저 삭제, 내 글 추천 금지, 매니저 표시는 회원이 못 바꿈)은 모두 DB에 있어요.
  공개 키가 브라우저에 보여도 이 규칙을 넘을 수 없어요.
- 로그인한 계정의 이름·이메일은 다른 회원에게 보이지 않아요. 화면에는 직접 정한 닉네임만 나와요.
- 이 Next.js는 지나온 화면을 숨겨 두었다가 뒤로 가기 때 그대로 보여 줘요.
  글쓰기 폼과 드림 스쿼드 만들기는 링크로 새로 들어올 때만 새로 시작하고, 응원톡은 다시 연결될 때 그사이 메시지를 채워요.

### 드림 스쿼드

- FC온라인 선수 카드로 포메이션(4-3-3, 4-2-3-1, 4-4-2, 4-1-2-1-2, 3-5-2, 3-4-3)에 맞춰 베스트 11을 짜요.
  누구나 만들어 볼 수 있고, 저장은 회원만 해요. 저장 전까지는 그 브라우저에 남아서 로그인하러 다녀와도 그대로예요.
- 저장한 스쿼드는 누구나 링크로 보고, 만든 사람은 **카페에 자랑하기**로 글에 붙여 올려요. 스쿼드를 지우면 글에서만 빠져요.
- 선수 목록·시즌 목록·선수 사진은 [넥슨 Open API](https://openapi.nexon.com/ko/game/fconline/)의 FC온라인 자료로,
  API 키 없이 받아요. 선수 목록은 서버가 받아 메모리에 하루, 시즌 목록은 캐시에 며칠 들고 있어요.
  넥슨 규칙상 받아 둔 자료는 30일 안에 새로 받아야 해서 그보다 짧게 잡았어요.
- 넥슨 Open API 약관에 따라 FC온라인 자료를 보여 주는 화면에 "Data based on NEXON Open API"를 적어요.
- 오버롤·능력치·급여·시세는 넥슨 Open API에 없어서 보여 주지 않아요.
- 같은 선수는 시즌이 달라도 한 번만 넣을 수 있어요(카드 번호 끝 6자리가 선수 번호예요). 한 회원은 30개까지 만들어요.
  저장할 때 서버가 카드 번호를 넥슨 선수 목록에서 다시 확인하고 이름도 거기서 가져와요. DB도 자리 수와 모양을 확인해요.

### 선수 맞히기

- `/cafe/game`에서 FC온라인 카드 사진을 보고 보기 4개 중 선수 이름을 골라요. 회원만 풀 수 있고, 한국 시간으로 하루 5문제까지예요.
- 정답은 1골이고 연승마다 1골씩 더 받아요. 2연승 2골, 3연승 3골, 5연승부터는 정답마다 5골이에요.
  틀리면 연승이 끊기고 다음 정답은 다시 1골부터예요. 연승은 날이 바뀌어도 이어지고, 받은 골은 등급과 골 상점에 그대로 쓰여요.
- 문제 은행은 DB의 `quiz_players`예요. 카드가 20장 넘게 나온 선수와 ICON 시즌(레전드) 선수 중 사진이 있는 365명이 들어 있어요.
  `npm run quiz:players`를 실행하면 넥슨 카드 목록으로 `supabase/schema.sql` 안의 목록을 다시 만들고,
  SQL Editor에서 다시 실행하면 DB에 들어가요. 목록에서 빠진 선수는 DB에 남아 있어도 괜찮아요.
- 문제 내기와 채점, 골 지급은 DB 함수(`quiz_start`, `quiz_answer`)만 해요. 안 푼 문제가 있으면 새로고침해도 같은 문제를 다시 주고,
  최근 30문제에 나온 선수는 다시 내지 않아요. 낸 문제와 문제 은행은 회원이 직접 읽을 수 없어서 정답이 새지 않아요.
- 넥슨 사진 주소에는 선수 번호가 들어 있어서 화면에 그대로 주면 보기와 맞춰 볼 수 있어요.
  그래서 서버가 비밀 키(`SUPABASE_SECRET_KEY`)로 정답 선수를 읽어 `/cafe/game/photo`로 사진만 대신 넘겨줘요.
  비밀 키가 없으면 문제를 낼 수 없다는 안내만 보여요.
- **이 기능을 배포하기 전**: `supabase/schema.sql` 전체를 SQL Editor에서 다시 실행해 주세요.
  `quiz_players`, `quiz_rounds` 표와 함수, `profiles.quiz_streak`, 골 내역 종류 `quiz`가 추가돼요.
  배포한 뒤에는 카페 관리의 업데이트 알림으로 회원에게 알려 주세요.
- `npm run test:cafe`가 문제 받기, 채점, 연승 골, 하루 상한, 권한을 PGlite에서 같이 확인해요.

### 승부차기 러시

- `/games/penalty`는 Supabase 설정이나 로그인 없이도 연습할 수 있어요. 홈·카페의 배너와 상단 게임 메뉴에서 들어가요.
- 한 판 10번, 슛마다 3.5초예요. 초록 구간은 100점, 금색 중앙은 150점이고 연속 성공마다 보너스가 25점씩 붙어요(최대 100점). 만점은 2,250점이에요.
- 한국 날짜에 따라 목표·속도·출발 위치가 바뀌고 같은 날은 모두 같은 조건이에요. 연습 최고점은 해당 브라우저에만 저장해요.
- 로그인하고 닉네임을 정한 회원은 오늘의 순위에 도전할 수 있어요. `supabase/schema.sql`을 SQL Editor에서 다시 실행하면 새 표와 함수가 추가돼요. 별도 비밀 키는 필요 없어요.
- 하루 최고점만 순위에 남고 동점은 공동 순위예요. 게임 시작 시각의 한국 날짜로 기록해서 자정을 넘겨 끝내도 원래 날짜에 저장돼요. 점수는 카페 골 포인트와 별개예요.
- 서버는 본인 게임인지 확인하고 10개의 슛 시각으로 점수를 다시 계산해요. 형식·진행 시간·5분 만료를 검사하고, 기록 저장 재시도는 중복 반영되지 않아요. 클라이언트 타이밍 게임이므로 자동 입력까지 방지하는 구조는 아니에요.
- 회원당 마지막 게임 한 개와 날짜별 최고점만 보관해요. 새 게임을 시작하면 이전 게임은 저장할 수 없어요. 점수 표는 브라우저가 직접 읽거나 수정하지 못하고 순위 함수가 닉네임·점수만 공개해요.
- 도전장에는 날짜와 목표 점수가 담겨요. 지난 날짜 도전장은 당시 기록이라고 표시하고 오늘의 조건으로 플레이해요. 링크의 점수는 순위에 등록되지 않아요.
- `npm run test:penalty`로 화면/DB 채점 일치, 권한, 중복 저장, 순위, 날짜 경계를 확인해요.
- 로컬 서버를 켠 뒤 `npm run test:penalty:browser`로 Edge에서 모바일·PC 화면, 10번의 슛, 시간 초과, 키보드, 공유 대체 경로, 재도전을 확인해요. 임시 프로필만 사용하며 `PENALTY_TEST_BROWSER`와 `PENALTY_TEST_URL`로 실행 파일과 서버 주소를 바꿀 수 있어요.

## Vercel 배포

1. 이 폴더를 GitHub 저장소로 올리고 Vercel에서 가져와요.
2. Vercel 프로젝트 설정의 Environment Variables에 `FOOTBALL_DATA_API_KEY`를 넣어요. 빌드할 때도 필요해요.
   카페를 쓰려면 Supabase 주소와 키도 넣어요(위의 "카페 설정" 참고).
3. 광고를 붙이면 Vercel 무료 플랜 약관상 상업적 이용이라 유료 플랜이 필요해요.

## 한글 팀 이름 추가

`src/lib/teams-ko.ts`에 팀 ID와 이름을 넣으면 돼요. 팀 ID는 아래처럼 확인해요.

```bash
curl -H "X-Auth-Token: 내_키" https://api.football-data.org/v4/competitions/PL/teams
```

5대 리그, 챔피언십, 에레디비시, 프리메이라 리가, 챔피언스리그 참가팀은 들어 있어요.
브라질 리그, 코파 리베르타도레스, 국가대표는 영어 이름으로 나와요.

## 알아 둘 점

- 무료 플랜은 스코어와 일정이 몇 분 늦게 반영돼요.
- 라인업과 골 시간 같은 경기 상세 정보는 무료 플랜에 없어요. 그래서 경기 화면에는 점수와 응원톡만 있어요.
- Supabase 무료 프로젝트는 일주일 동안 아무도 안 쓰면 잠들어요. 대시보드에서 다시 켜면 돼요.
- 카페에는 사진 올리기, 신고, 검색 기능이 아직 없어요. 문제 글은 매니저가 지워요.
- API의 최종 점수에는 승부차기 골이 합쳐져 있어서, 화면에서는 정규·연장 점수와 승부차기 점수를 따로 계산해요.
- 끝난 토너먼트는 순위표 API가 404를 줘서 "순위표 없음"으로 보여 줘요.
- `npm audit` 경고는 린트 도구 쪽 패키지에만 해당해요. `npm audit fix --force`는 린트 설정을 옛 버전으로 내리니 실행하지 마세요.
